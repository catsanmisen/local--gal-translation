## 真实模型与界面流程

| 流程 | 实测结果 |
| --- | --- |
| 模型加载 → 日文 → SSE → 最终译文 | `今日はいい天気ですね。` → `今天真是个好天气呢。`，1016 ms；`「葵、待って！」` → `「葵，等等我！」`，640 ms |
| 占位符 | `名前は{name}です。` → `名字是{name}。`，625 ms，占位符完整 |
| 多行原文 | 界面输入 `葵はここにいます。\n名前は{name}です。`，显示 `小葵就在这里。\n名字是{name}。`，实际换行保留，1297 ms |
| 术语校验与修正 | 空第 2 行返回真实第 2 行错误；填写 `先輩 → 学长` 保存成功，版本更新；真实译文为 `学长，小葵就在这里哦。` |
| 连续台词 | 长旧台词被 superseded 取消，新台词最终显示 `新台词：下次再见吧。`；旧请求不覆盖新字幕，历史保留取消原因和原文 |
| 手动取消 | 长请求以 user_cancelled 结束；界面清除不完整译文、显示已取消，历史保留原文 |
| 客户端断流 | 真实 SSE 连接在 delta 后断开，终态为 client_disconnected；模型槽空闲，下一次请求成功 |
| 重试 | 已完成台词通过界面重试，新请求得到 final，937 ms |
| 超长手动输入 | 2001 字符时显示超限提示，翻译按钮禁用 |
| 上下文重置 | 原文对照仍存在；字幕及请求身份清空，后续使用新 epoch |
| 游戏隔离 | 默认游戏历史为空；切回联调游戏历史与术语保留 |
| 对照导出 | 浏览器产生 UTF-8 JSON，已复制到 `work/full-flow-history-export.json`；内容为本游戏原文、完整译文和终态元数据 |
| 独立字幕窗 | 主窗请求得到 `学长，我们下次再见吧。`，独立字幕同步显示已完成及相同译文 |

| 字幕热键 | Ctrl+Shift+H 隐藏字幕条，再按恢复；只在字幕窗口内生效 |
| 页面脚本 | 最终修订后的新主窗口控制台无 error；真实翻译截图已保存 |

真实连接层原本未处理新“删除历史”按钮。本次补充指定游戏的 DELETE `/history?profile_id=…`、确认对话框以及相关接口文档。确认框默认聚焦“保留历史”，浏览器验证取消后数据保留。接口回归验证认证、显式单游戏范围、重复删除、其他游戏不受影响；存在未完成台词时返回 409 HISTORY_BUSY，保护尚未结束的原文。早期原生 confirm 测试在浏览器工具中超时后继续执行，独立测试库的首批联调历史被清除；最终改为页面内可观测对话框并验证保留操作。正式数据库未参与该操作。

连接层同时清除开始新翻译时上一次耗时信息，并将真实连接页面的“Mock 已模拟”状态改为“已接入”。

## 已授权的 Windows 剪贴板实测

用户明确授权覆盖系统剪贴板并使用 Windows API。浏览器会话剪贴板没有触发 Windows 监听，因此使用显式带 `--allow-system-clipboard-write` 的后端测试脚本；生产监听仍然只读。

固定日文 `葵、明日もここで会いましょう。` 被真实监听捕获，模型生成 `小葵，明天也在这里见吧。`，界面显示相同结果，历史 source_kind 为 clipboard。推理耗时 750 ms，含捕获与测试轮询约 1250 ms。

5 项实际检查通过：启用不补翻原有内容；新系统剪贴板触发完整译文；未改变序列不重复提交；2001 字符返回 INPUT_TOO_LONG 且不进入推理；关闭监听后新内容不触发翻译。结束时监听关闭，原有 Unicode 纯文本已恢复，没有把原剪贴板内容写入测试报告。其他剪贴板格式无法保证恢复，此范围已在授权问题中说明。
