## 首版目标与分工

面向 Windows 的本地日语→简体中文客户端，运行现有 GalTransl 4B Q6_K。推荐 C# WPF；前端可自行决定界面实现，但应遵守接口契约。界面提供启动、输入、字幕、术语和状态管理。

| 后端负责 | 前端负责 |
|---|---|
| llama.cpp 生命周期、健康检查、显存检测与 GPU 层数选择 | 窗口、托盘、快捷键、悬浮字幕、DPI 与主题 |
| 提示词、采样配置、上下文预算、翻译及格式检查 | 原文输入、译文显示、历史查看、风险提示 |
| 单推理队列、过期请求处理、去重与完整句等待 | 提供文本事件序号、源类型、时间与完成标记 |
| 会话、术语表和游戏配置的数据保存、状态接口 | 配置编辑、游戏/输入源选择、捕获区域交互 |
| 推理取消、暂停与资源恢复策略 | 显示相应状态、提供重试/暂停按钮 |

首个联调版本实现手动输入和剪贴板事件。HOOK/OCR 在下一阶段由前端输入适配层提供原始日文事件，后端进行排队和翻译；暂不假定任何 HOOK/OCR 组件已安装。HOOK 引擎选型与进程注入桥接另行联调，前端不得将示例输入视为真实自动取词。

## 必做界面

1. **主窗口**：当前游戏/会话、输入来源、启动/停止翻译、暂停采集、服务状态、可用显存、最近错误。初始化连接后台，不在 UI 线程启动等待或执行 HTTP。
2. **输入与预览**：日文多行手动输入；剪贴板监听开关默认关闭，由用户打开；显示原文、来源和说话人（确实取得时）。同一次监听事件避免回写剪贴板形成循环。
3. **悬浮字幕**：置顶、可移动、字体大小、透明度、原文/译文切换、隐藏快捷键、可选鼠标穿透。默认使用独立字幕窗；窗口化/无边框先验收，独占全屏单独验证。字幕不要进入自己的 OCR 区域。
4. **术语表**：日文词、中文译名、备注；增删改与 UTF-8 导入导出；更新后调用后端保存，显示版本和验证错误。
5. **历史**：有限分页或虚拟列表，显示原文、最终译文、耗时、警告、来源；不把未完成流式文本当成最终历史。切换游戏/读档可一键清空上下文。
6. **游戏配置**：保存显示设置、输入源与未来 OCR 区域；输入适配器不支持时显示清晰状态。配置与全局设置分开。

首版不做模型选择、复杂采样参数、音频识别、自动游戏内文本替换；后续确有需要再扩展。

## 状态与行为要求

- 服务状态：`stopped / starting / loading / ready / translating / paused / recovering / error / stopping`。`paused` 与 `recovering` 是计划能力，当前旧脚本仅会在低显存时停止。
- loading 可以显示持续时间与阶段；只有后端报告可测进度时才显示百分比，不能自行生成假进度。
- 显示显存可用值和后端保留阈值（默认 2048MiB）；显存不足时显示原因与操作入口，禁止前端绕过保留阈值。
- 同一会话的 `sequence` 单调递增。前端先登记 `request_id`，仅接受当前会话、当前台词的流事件；过期请求的结果可记录但不能覆盖新字幕。重置后使用新 `epoch`。
- 中文增量显示时标为“翻译中”。只有 `final` 才标为完成；格式错误、截断、取消都不能冒充完整译文。流断开且未收到终态时显示中断，可让用户重试，不自动多次重复提交。
- 快进时允许暂停翻译；回滚/读档先调用会话重置。重置响应回来后才能用新 epoch 提交。
- 原文保留：所有进入翻译流程的日文原文（手动、剪贴板及后续 HOOK/OCR）必须原样保留，不修改、不丢失、不被译文覆盖。字幕始终可切换查看原文；历史完整保存原文与译文对照并支持导出；错误、取消、截断等任何场景下原文都不得丢弃或替换。
- 风险提示轻量展示“需复核”，可查看原因；规则提示不显示成模型置信度或正确率。
- 退出时请求停止自己管理的后台。前端崩溃后的回收由后端补充；不能通过进程名批量杀死用户其他模型服务。

## 前后端连接

计划客户端后端地址：`http://127.0.0.1:18039/api/v1`。现有模型内部地址：`http://127.0.0.1:18038/v1`。**18039 尚未启动或实现，前端首版可按 mock 开发。** 正式前端应通过客户端后端，不直接拼提示词或绕过队列调用 18038。

API 详见同目录《接口契约.md》。启动器将提供每次启动的随机会话 token；前端从启动结果取得地址和 token，不在日志、URL 或设置文件保存 token。连接只绑定本机，无远程开放要求。UI 不暴露这类实现细节给普通使用者。

## 前端交付与验收

前端交付放 `frontend/`，附 README、构建/运行步骤、依赖清单。界面 mock 与真实模式明确区分；对接本目录 fixtures 即可先开发，不需要加载 4B 模型。

验收至少覆盖：中文/日文多行与名字；流式正常完成；模型加载失败；低显存暂停；取消；切换会话；快速翻页后旧请求晚到；流中断；术语更新失败；DPI/窗口缩放；退出回收。模拟错误后 UI 不冻结、不丢原文、不显示错误台词。

联合性能验收在真实游戏进行，完整台词稳定到完整译文以中位数≤1.5秒、P95≤3秒为首版目标；这不是现有端到端测量结果。
