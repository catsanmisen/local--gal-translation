# 客户端后端接口契约 v0.2

**归档说明：** 本页保留 v0.2 手动与浏览器入口细节。当前游戏自动会话、后端序号、取词能力、原生字幕、恢复与 Backlog 以 [v0.3 契约](接口契约-v0.3.md) 为准；下文“尚未实现”等状态描述仅反映原版本。

状态：客户端 API 已实现，2026-10-10 完成真实 GalTransl 4B 联调。原前端文件保持由前端开发者管理；后端通过 `backend/bridge/` 适配现有 DOM。只用于本机 Windows 日语→简体中文。

## 基本约定

- 根地址：`http://127.0.0.1:18039/api/v1`；UTF-8 JSON。所有接口要求 `Authorization: Bearer <启动器返回的随机token>`。仅绑定 127.0.0.1，不启用通配 CORS。
- 时间使用 ISO 8601 UTC；耗时毫秒；显存 MiB。ID 为字符串；sequence、epoch 为整数。
- 通常返回 HTTP 200/201/202；错误为非 2xx JSON：`{"error":{"code":"ENGINE_NOT_READY","message":"模型仍在加载","retryable":true},"request_id":null}`。
- 所有未知字段可以忽略；不得改变已有字段含义。前端从 `/status` 的 capabilities 判断尚未实现功能。
- 推理参数和历史由后端管理。默认单个活动游戏会话，单推理请求；多窗口不得自行创建并行推理。

## 接口一览

| 方法与路径 | 输入 | 结果 |
|---|---|---|
| GET `/status` | 无 | 服务状态、模型、显存、活动请求、能力 |
| POST `/engine/start` | `{}` | 202；启动接受，前端轮询状态 |
| POST `/engine/stop` | `{}` | 202；停止接受，取消队列并释放模型 |
| POST `/sessions` | `{"profile_id":"default"}` | 201；`session_id`、`epoch`、`glossary_version` |
| POST `/sessions/{id}/reset` | `{"reason":"scene_change"}` | 200；新 epoch；取消该会话旧请求并清空翻译上下文，保留原文对照历史 |
| PUT `/sessions/{id}/glossary` | `{"entries":[{"source":"葵","target":"葵","note":"人物名"}]}` | 200；新 glossary_version 与 epoch，取消旧请求并清空旧上下文 |
| POST `/translate` | 下述对象，stream=true | 成功为 POST 响应 SSE 流 |
| DELETE `/requests/{request_id}` | 无 | 202；取消接受；最终取消状态见流或请求状态 |
| GET `/requests/{request_id}` | 无 | 请求状态和终态结果，用于断流后确认 |

前端 GET `/status` 在可见/运行时每 1 秒一次，空闲隐藏时可放缓；轮询不阻塞界面。停止/取消接口幂等。停止只管理本客户端启动的进程。

## 状态响应示例

```json
{
  "api_version":"0.1",
  "state":"ready",
  "message":"模型就绪",
  "model":{"id":"galtransl4-ja-zh","quantization":"Q6_K","context_tokens":2048,"gpu_layers":7},
  "gpu":{"free_mib":2683,"reserve_mib":2048,"sampled_at":"2026-10-10T09:00:00Z"},
  "active_request_id":null,
  "capabilities":{"streaming":true,"cancel":true,"auto_recovery":false,"text_events":false},
  "last_error":null
}
```

以上数值是示例，不是实时状态。GPU 采样失败时 `gpu` 可为 null，必须报告原因。样本过期不能当作当前值；前端显示后端返回的 degraded/error 状态。引擎状态枚举与《前端需求.md》一致。

## 翻译提交

```json
{
  "request_id":"req-0001",
  "session_id":"session-demo",
  "epoch":1,
  "sequence":1,
  "source_text":"今日はいい天気ですね。",
  "source_kind":"manual",
  "speaker":null,
  "captured_at":"2026-10-10T09:00:00Z",
  "complete":true,
  "stream":true
}
```

首版只接受 `manual / clipboard`、complete=true。source_text 为非空 UTF-8 字符串，首版上限 2000 字符；另受总 token 预算约束，超限必须明确返回 `INPUT_TOO_LONG` 或 `CONTEXT_LIMIT`，不得静默截断。speaker 只传确实提取到的姓名，不推测。

request_id 由前端生成 UUID 或等价唯一字符串。会话内 sequence 严格递增，epoch 必须匹配；新请求使此前未完成请求失效。相同 ID、相同 body 以现有请求处理，不能重复推理；相同 ID 不同 body 返回 `REQUEST_CONFLICT`。断流后先查请求状态，不盲目重发。会话只保留最近 128 个请求终态，过期查询返回 404。

HOOK/OCR 阶段另增加 `/text-events`，允许 complete=false 并由后端做稳定等待/去重；该接口当前不在首版承诺内，不应把半句直接提交 `/translate`。

## POST SSE

前端用 HTTP 流式读取（POST，不能直接使用只支持 GET 的 EventSource）。每个事件是 `event:` 与单行 JSON `data:`，以空行分隔。按 SSE 规则累积字节并正确解析跨块 UTF-8，不能假设一次网络读取就是一个事件。

```text
event: meta
data: {"request_id":"req-0001","session_id":"session-demo","epoch":1,"sequence":1,"status":"running"}

event: delta
data: {"request_id":"req-0001","session_id":"session-demo","epoch":1,"sequence":1,"text":"今天"}

event: delta
data: {"request_id":"req-0001","session_id":"session-demo","epoch":1,"sequence":1,"text":"真是个好天气呢。"}

event: final
data: {"request_id":"req-0001","session_id":"session-demo","epoch":1,"sequence":1,"translation":"今天真是个好天气呢。","elapsed_ms":869,"warnings":[],"context_committed":true}

```

最终以 final.translation 替换增量缓冲，不假设其一定等于已收到 delta 拼接。所有事件均带同样的身份字段。

已接受请求只能有一个终态事件：`final / cancelled / error`；idle 心跳使用 SSE 注释。queued/running 期间可以发送 `meta`。取消事件 reason 的合法值为 `user_cancelled / superseded / session_reset / engine_stopped / client_disconnected`；最后一项表示最后一个流读取者断开连接。流开始前错误用 HTTP JSON；流开始后错误用 SSE error。

取消后的计算槽回收超过等待窗口时，仍保留 cancelled 的原始 reason，另附 `diagnostic:{code:"CANCEL_TIMEOUT",message,retryable,occurred_at}`。状态 last_error 同样保留该诊断，直到手动停止或重新启动；模型不会因为槽位未确认空闲而继续接受推理。

断开客户端连接应取消没有其他读取者的请求。取消确认前，后端仍可能在回收计算；前端不能据 202 自行认为模型空闲。真正完成/取消才释放调度槽。正在旧 epoch 中处理的请求不得提交上下文。被取代请求若刚完成，其语义结果可存历史，但新字幕不得被覆盖；历史提交必须在 sequence/epoch 仍有效时原子执行。

## 错误与警告

| code | UI 行为 |
|---|---|
| ENGINE_NOT_READY / ENGINE_STOPPED | 保留原文，提示状态，允许就绪后重试 |
| VRAM_LOW / GPU_MONITOR_UNAVAILABLE | 提示暂停或恢复中，按后端状态处理 |
| STALE_EPOCH / STALE_SEQUENCE | 丢弃过期请求；使用最新会话信息 |
| INPUT_TOO_LONG / CONTEXT_LIMIT / INVALID_GLOSSARY | 显示输入位置或原因，供用户修改 |
| GENERATION_TRUNCATED / FORMAT_DAMAGE | 展示失败和原文，不将片段标为完成 |
| REQUEST_CONFLICT / UNAUTHORIZED / INTERNAL_ERROR | 记录脱敏诊断并提示重新连接或重试 |
| STORAGE_ERROR | 保存失败，不将结果标为完成，不提交翻译上下文；已接受请求的原文仍已登记 |
| CANCEL_TIMEOUT | 说明计算槽回收超时导致模型停止，提示重新启动 |
| UI_LAYOUT_MISMATCH / UI_UNAVAILABLE | 原前端布局或文件正在变化，更新连接层或完成前端更新后刷新 |

成功结果 warnings 为 `{code,message}` 列表，如 inferred_gender、context_sensitive。这些是规则提示，不是置信度。高风险人称结果可返回 context_committed=false，避免自动污染后续上下文。

## 已实现的配置、历史与输入接口

| 方法与路径 | 输入/结果 |
|---|---|
| GET `/profiles` | `[{id,name,glossary,prefs,glossary_version}]` |
| PUT `/profiles` | `{id,name,prefs}`，创建或更新显示设置；术语仍通过会话术语接口更新 |
| GET `/settings` | `{theme:"dark"}`，也支持 light/system |
| PUT `/settings` | `{theme:"dark"}`，返回保存值 |
| GET `/sessions/{id}/glossary` | `{entries,glossary_version}` |
| GET `/sessions/{id}/history?limit=5&offset=0` | 当前会话的 `{items,limit,offset,has_more}` |
| GET `/history?profile_id=default&limit=5&offset=0` | 游戏的跨会话对照历史；limit 为 1–200，offset 为 0–10000 |
| DELETE `/history?profile_id=default` | 永久删除指定游戏的历史，返回 `{deleted,profile_id}`；必须显式指定单个存在的游戏；该游戏有未完成台词时返回 409 `HISTORY_BUSY`。界面执行前二次确认，不重置翻译上下文 |
| GET `/subtitle` | `{ja,zh,state,prefs,request_id?,session_id?,epoch?,sequence?}`，只显示当前有效台词 |
| PUT `/clipboard` | `{enabled:true/false}`；Windows Unicode 剪贴板监听，默认关闭 |
| GET `/engine/slots` | `[{id,is_processing}]`，用于验证取消后计算槽回收，不返回提示词 |
| POST `/lease` | `X-Client-Id: <窗口UUID>`，主窗口心跳 |
| DELETE `/lease` | 相同窗口编号，关闭主窗口时释放 |
| POST `/shutdown` | `{}`，停止本客户端模型并退出 API |

`prefs` 的字段为 `font`（14–40）、`opacity`（20–100）、`mode`（both/ja/zh）、`source_kind`（manual/clipboard）。滑杆数值为整数，不允许提交任意模型参数。术语版本随游戏配置持久化。

历史条目含原样的 `source_text`、`source_kind`、`speaker`、`request_id`、`at`、`terminal`、`translation`、`reason`、`elapsed_ms`、`warnings`。只有 final 有最终译文；失败或取消的片段不会作为完成译文保存。历史保存最多 10000 条终态；请求状态仅保留最近 128 个无读取者的终态。重启时未完成的持久化条目转为 interrupted，保留原文。

状态响应额外含 `session`（当前会话或 null）、`clipboard`（enabled/last_error）及 `owned_pid`。`capabilities.native_subtitle=false`、`text_events=false`、`auto_recovery=false`：没有承诺 Windows 原生置顶/穿透、HOOK/OCR 或显存降档自动重启。显存采样过期会报告 recovering 和 GPU_MONITOR_UNAVAILABLE，停止接受新台词；低显存会停止模型并报告 paused，需用户手动重新启动。

`translating` 由会话层在引擎 ready 且存在活动请求时合成；不会覆盖 paused/recovering/error 等保护状态。引擎自身负责加载和资源状态。

`clipboard.last_error` 可附 `severity`（notice/error）、`occurred_at`（UTC）和 `revision`。同一占用事件的 revision 与时间不变；恢复后再次出现会递增 revision。CLIPBOARD_BUSY 应在输入状态行轻量显示，不反复弹错误横幅；其他相同错误在同一事件内关闭后不自动重开。

`/subtitle` 额外提供 `reason`、`warnings`、`elapsed_ms`、`diagnostic`。重置时清空旧 request_id 和终态信息；失败/取消不提供可冒充完整结果的 zh 片段。

打开 `http://127.0.0.1:18039/app/` 使用连接视图。该页面从同源 `/bootstrap` 取得仅驻内存的随机 token，然后所有 `/api/v1/*` 请求使用 Authorization 头。`/bootstrap` 位于 API 外，具有 Host/Origin/跨站检查；不启用通配 CORS。内部 18038 另有只传给模型子进程环境的随机凭据，不向前端返回。

威胁模型为本机单用户：这些凭据隔离浏览器跨站调用和意外调用，不能防御本机恶意进程。本机非浏览器进程仍可读取 `/bootstrap` 并调用 API；`control.py` 也使用该机制。未来若改为受 ACL 保护的本机 IPC 或收紧 bootstrap，启动器、控制脚本与连接层必须同步迁移。

`/bootstrap` 同时返回 `ui_contract` 版本。实际交互与字幕呈现的来源为 `backend/bridge/`；布局来自 frontend 的只读静态资源。必需控件 ID 或脚本入口变化会返回明确的 UI_LAYOUT_MISMATCH。协作约定见《前后端连接约定.md》。

最后一个主窗口离开后停止模型；主窗口异常失联的心跳超时为 90 秒。字幕预览窗口不保持模型运行。后台 API 仍可运行以供重新打开主窗口，完整退出使用 `/shutdown` 或停止脚本。旧 CLI 18038 与私人客户端不可同时管理同一端口。
