# 总览复核、修复与真实游戏短测（2026-10-12）

## 当前结论

SeaBed 与苍之彼方的四重奏 EXTRA2 已实际启动并显示日文，完成 WGC → 离线 RapidOCR → GalTransl 4B Q6_K → 原生字幕的探索性验证。最新源码回归 **317 项通过**：Python 126、桌面 153（含隔离真实后台 12 项）、桥接 7、Mock 22、Backlog 5、SSE 4；既有 **41 项独立 API 冒烟**也重新通过。317 项由原 271 项基线增加 46 项，不能与实机台词数混算。

## 实机触发的修复

| 触发与问题 | 实现及复核 |
| --- | --- |
| 退出后立即重启，启动请求被发给正在退出的宿主 | `--shutdown`等待原实例释放互斥锁，超时返回失败；正常停止/重启已复测 |
| 框选区域时设置窗遮住游戏 | 框选期间隐藏设置/位置窗，将游戏置前，完成后恢复设置窗；Aokana 实际框选通过 |
| 横排一句被检测成两个相邻片段，右半句被当背景排除 | 同行片段合并，最多复核 8 个合并行；窗口模式七次喘息由原三次漏捕恢复到完整行 |
| 16:10 全屏与窗口的黑边变化切掉字形顶部 | OCR 裁图增加有界边距，保持保存区域，按实际裁图映射识别边界；全屏复测通过，完整七次喘息可见，仍有个别字形误识 |
| 检测框过紧导致括号缺失/误读 | 对异常外层括号最多复核 8 行，不再检测整帧；只接受置信度不降低、正文逐字一致、图像重新识别出成对括号的结果。真实“どん”六次样本前后裁图、JSON在案 |
| NVL 稳定超时的空事件把旧页前缀清掉，随后整页重翻 | 超时标记先于空事件；暂态保持已接受前缀，真正空页仍清空。SeaBed 长追加段落经历超时后只翻译新增三行，耗时 4.969s；旧整页重翻 9.203s保留 |
| 长字幕备用区盖住对话框姓名牌 | 框外备用位置保护整块已配置对话框；Aokana 姓名和原文保留可见，短译文可放框内空白区 |
| 切出游戏时采集投递被拒，旧暂停提示残留 | 只对当前采集版本处理拒收；前台竞争返回后重放最新新增段落，忽略旧版本错误 |
| 空菜单留下大底衬，章节箭头被读成“ンン”并翻译 | 无当前原文时隐藏字幕与按钮；精确过滤已观察的章节标签和箭头变体。最新实机章节菜单为 idle、request_id=null，无字幕底衬 |
| Textractor 名称含冒号/方括号、二进制输出与内嵌线程头污染正文 | 严格解析头边界，拒绝异常长度/控制符/内嵌头；每次扫描只保留有界线程更新，合并到桌面定时处理，避免 WPF 回调堆积 |
| 绝对 JIT 地址与动态上下文不能随游戏重启恢复 | 桌面拒绝保存/重插此类线程，旧配置退回 OCR；只支持模块相对 code 与固定上下文。不能据此宣称所有引擎 HOOK 可恢复 |
| 游戏启动窗口变化，旧模型仍在停止时重绑定进入永久 blocked | 增加 waiting_owned_stop，所属退出完成后重启；永久启动错误保留 recovery_error，不能被心跳清掉，等待原文结束为明确错误而非无限“翻译中”。复测游戏启动后模型 ready，退出自动释放 |
| 刷新包时游戏仍映射相同 Textractor DLL，复制失败 | 刷新前比较大小与 SHA256，相同文件不重复覆盖；不修改游戏 DLL 或安装文件 |

变量/控制符校验、提示词回显拒收、一次有界模型修复均保持。OCR视觉换行仍可按中文重排并保留原文；没有通过放宽模型校验来消除错误。旧失败语料在新真模型上的系统复现仍未完成。

## CPU与延迟

先在独立候选中设置 max_gpu_layers=0 测 CPU；该设置随后恢复为原始 **100**。正常配置、两款游戏及壁纸并行时，客户端根据真实显存自动选择 CPU（gpu_layers=0、模型进程 --device none），原生字幕继续显示。保存了 `automatic-mode-start.json`、`automatic-cpu-final.json`。另一游戏退出后可用显存回到约3132MiB，CPU模型 PID保持相同，未自动重启升GPU。

探索统计来自 `cases.jsonl`，按会话/请求去重，保留冷启动、重启重放及慢样本。32次读取中29个独立 final、3次未获得新终态；后者含输入没有实际推进与采集等待，原始记录全部保留。OCR字符串种类不是人工确认的台词数量。

该表只涵盖带同期状态的case记录，不是本轮全部输出。另将原生日志的全部80个独立final回调保存为`native-displays-all.jsonl`：所有模式合计elapsed中位2.000s、P95 4.969s、最大10.140s，包含菜单误捕、重启及无人连续对照的推进，不能作为某一模式或50句验收结果。此前Aokana CPU长句5.109s、GPU/混合长句3.875s等也保留在原生日志中，不因缺case身份而删除或算作快速样本。

包内配置恢复正常GPU层数上限，ZIP不含测试数据库、日志、work、凭证或玩家存档。版本和每个文件的SHA256见包清单，许可证及Textractor对应源码继续随包。建议将ZIP解压到新目录使用，勿覆盖正在运行的版本。旧completion/reliability ZIP保留供回退。

下一轮优先处理：

1. 将本轮全部失败/慢样本按构建与场景分类；对旧“空译文/变量/换行/回显”语料在真模型复现，核对一次有界修复及历史保留。
2. 针对Aokana波浪号/省略号演出、括号和字形波动补样本；已观察一次约25s没有稳定台词，下一句恢复。这一漏捕未被本轮修复结果抵消。
3. 用相同正文、相同上下文比较CPU与少量GPU层混合；在现有Q6基线上优化整页冷同步和稳定等待，保留全部慢样本。
4. 冻结构建后两款OCR各50句人工对照；找到实际支持且可恢复的HOOK游戏再完成两款各50句。不能用扫描组件运行代替有效线程验收。
5. 按计划补快进、读档/回滚、菜单、重启、Alt+Tab、最小化、DPI/跨屏；Magpie仍后置。GPU/混合与CPU各30分钟并行，补CPU/RSS及资源采样。
6. 完成离线新目录首次启动、升级/回退和许可走查后，再升级正式目录。

继续执行5小时窗口剩余低于2%时停止新增实现/测试的规则。本轮最后可读取额度时剩余62%，未触发暂停阈值；期间部分额度查询失败，没有把不可读当作0%或100%。
