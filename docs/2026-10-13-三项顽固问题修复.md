## 特殊演出：根因与修复

1. 精确字符串稳定策略被引号、波浪和省略号的 OCR 字形变化反复重置。加入有限观察窗，要求完整原文至少三次支持、同一键至少两次、跨度至少 600ms；提交的是实际观察到的一整段原文，不拼接猜测字符。严格增长的逐字前缀清除观察窗，HOOK 仍采用原来的精确稳定判断。
2. 已完成的很短末行偶尔缺失或错读，导致整页字幕被清空。长正文与极短末行匹配时沿用 1500ms、有至少三次采样的确认期；完整原文重新出现会取消误读计时。持续真实短句变化、确实缩短的页面仍可推进。
3. 新增行选择与稳定器对引号误读的判断不一致，把末尾 OCR 的 `J` 误认作 NVL 新增字符。`PageText` 与 `TextStabilizer` 共用演出等价判断，保留负号、真实数字标点、引号内字母、独立新行 `J` 和新增纯省略号行。
4. `Coordinator` 命中已完成整页时原来直接跳过稳定器，使误读计时跨越正确原文累积。现在同页快速路径仍确认完整原文证据，同时保留无重复推理与布局跟随。

初始修复并未直接通过实机保持：`aokana-wave-first-attempt.jsonl` 与 `aokana-wave-v4-final-hold.json` 保留了重复清空、重译及只剩 `J` 的失败。它们没有被删除或记作成功。最终 v6 才通过同一游戏页面的持续保持和下一句检查。当前仍有 `んっ`→`んつ`、引号→`Г` 等 OCR 字形错误，可能影响译词；本轮没有把它们人工改成正确原文，也不宣称通用 OCR 准确率已经达标。

## 格式失败：重放与约束

从旧日志、数据库提取八个不同失败原文，保留历史 OCR 错字、异常字符及可恢复的前文，不先清洗成正确日文再测试。最终实际模型重放的八个原文均为 final，耗时为 6.765 / 1.391 / 4.563 / 1.890 / 3.313 / 4.531 / 6.437 / 8.328 秒。另验证具名变量、printf、控制符、空行、HOOK 多行与特殊演出，总计 16 项。

真实 Q6 printf 探针曾连续丢失 `%d`。普通“再次强调保留变量”和只替换占位符不足以修复；最终采用一次有界受保护重试：

- 原文每个变量/控制符映射到不同的 `{GT_KEEP_n}`，格式重试使用空前文及独立短示例。
- 示例使用 `{GT_EXAMPLE_n}`，与实际请求隔离；抄回示例会被现有变量计数校验拒绝，不需要给合法算术译文添加字符串黑名单。
- 还原前后都做严格校验，缺失的变量不从原文补造；原位置变量顺序必须保留。失败不进入翻译上下文，历史保留原文，请求身份与单推理队列不变。
- 补上大写 `\N` 等引擎换行控制符的保护。自动 OCR/HOOK 不提前展示未校验片段。

最终 printf 探针在两次模型调用、共 4.156 秒后得到 `%s今年%d岁，余额是%02d。`。具名变量、控制符及多行探针全部完成。缺变量、示例回显、普通/礼貌体算术和旧请求取消等负面/边界检查均通过。

旧客户端未记录当时被拒绝的模型原始输出，因此本轮能重放旧原文与部分历史上下文，不能逐字复现所有旧坏输出。该证据限制保留；未来再出现相同错误应继续保存完整样本，而不是降低格式校验标准。
