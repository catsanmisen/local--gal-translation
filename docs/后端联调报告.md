# 后端构建与联调交付

日期：2026-10-10。

本轮完成后端与既有界面的真实翻译闭环。运行 [启动私人翻译客户端.cmd](E:/GalTranslClient/启动私人翻译客户端.cmd)，页面打开后点击“启动翻译”。详细操作见 [后端说明](E:/GalTranslClient/backend/README.md)。

## 已交付

- 只绑定本机的客户端 API，随机启动凭据，内部模型独立凭据，静态资源白名单。
- 现有 GalTransl 4B Q6_K 与 llama.cpp b11429 的自动启停；按实际显存分配 GPU 层数，保留 2048MiB 的保护阈值。
- Windows 子进程先以挂起状态创建，加入 kill-on-close Job Object 后恢复；回收只针对自己创建的模型进程。
- 一个推理 worker、一个最新待处理请求；重复 ID 幂等，冲突 ID 明确拒绝；所有 SSE 事件含完整身份，只提交有效 epoch/sequence 的上下文与字幕。
- POST SSE 流、取消、断流回收和终态查询；下一句推理前验证计算槽已释放。
- SQLite 中持久保存游戏配置、术语版本、显示设置及最多 10000 条终态历史；所有已接受请求先保存原文。
- 默认关闭的 Windows Unicode 剪贴板监听，不回写，按序号去重并等待文本稳定。
- `backend/bridge/` 中的目录外连接控制器。HTTP 响应读取原前端布局，替换脚本入口；原来的独立静态前端继续是 Mock。
- 浏览器字幕预览随有效台词更新，未完成结果有明确状态；本地打包图标后，连接视图不依赖 CDN。
- 更新的 v0.2 接口契约、启动/停止脚本及测试。

## 验证证据

23 项行为测试通过，包括队列取代、单并发、重复请求、取消、读档、术语版本、格式损坏、失败原文、异常退出恢复、游戏隔离、API 鉴权、断流、低显存、不接管其他模型以及启动中停止。随后针对前端并行更新后的图标路径做了兼容性测试，结果通过。

真实模型多轮联调通过。最终记录位于 [真实联调 JSON](E:/GalTranslClient/work/backend-real-smoke.json)：

| 预设输入 | 最终轮完整响应 |
|---|---|
| 今日はいい天気ですね。 | 907ms |
| 「葵、待って！」 | 625ms |
| 名前は{name}です。 | 656ms，控制符保留 |

术语“葵→小葵”生效；真实推理中断开流后获得 cancelled 终态，计算槽为空，下一句正常完成；内部模型接口无凭据访问返回 401。失败或取消的原文在持久化历史中得到验证。

浏览器实际操作已显示 GalTransl 的中文译文，单条预设句界面显示耗时 875ms。800×600 下主区高度保持在窗口内、内容在页内滚动，浅色字幕前景可读。最终入口使用本地 CSS、脚本和字体，默认游戏配置可切换，连接控制器无新增 JavaScript 错误。

真实测试结束后，后端状态为 stopped、owned_pid 为 null、active_request_id 为 null、剪贴板监听关闭。模型回收后另一次 NVIDIA 采样可用显存为 3728MiB；这是单次采样，其他应用占用也会变化。临时 API 服务已关闭，启动脚本可使用默认端口。

这些是预设文本的工程验证，不代表真实游戏内延迟、准确率或长期帧率验收。

## 前端边界

本次后端构建没有向 `frontend/` 写文件。构建过程中检测到前端文件在并行更新，保留了这些更新，并适配了新的本地图标路径。初始哈希与变化记录见 `work/frontend-before.json`、`work/frontend-preservation.json`；后者记录的是观察到的并行变化，不代表后端改写前端。

后端临时连接控制器和补充样式位于 `backend/bridge/`，后续前端正式接入可参考其传输与事件处理；不要把开启另一静态服务的 Mock 页面误当作真实入口。

## 剩余工作

Windows 原生字幕置顶/整窗穿透、托盘、全局快捷键、HOOK/OCR，以及低显存自动降档重启均尚未接入，能力字段没有宣称它们已完成。自身自动游戏取词和实际游戏长期验收仍需后续实现。当前可用闭环为手动输入或剪贴板完整台词到真实中文，再到主页面和浏览器字幕预览。
