# 客户端接口契约 v0.3（游戏旁实时翻译）

2026-10-11，当前游戏接口契约；桌面握手版本已增至2，见末尾reliability-2增量。v0.2的手动与浏览器入口保留；新增自动入口使用独立序号分配规则。布局在玩家授权后补充Backlog控件与js/backlog.js，连接层和布局校验同步更新，原生设置位于desktop。

## 身份和单一提交者

- 原 `/translate` 仍由调用端提供 request_id/session_id/epoch/sequence，sequence 严格大于当前会话值；只接受 manual/clipboard。游戏自动会话绑定期间返回 409 GAME_IN_USE，避免两端竞争分配序号。
- 自动 `/text-events` 不接受调用端 sequence。桌面提供 game_session_id、epoch、line_id、event_id；后端在 client.lock 内原子分配 sequence。字幕和请求仍以 request_id/session_id/epoch/sequence 四要素防止迟到结果。
- source_kind 的持久化枚举扩展为 manual/clipboard/ocr/hook；OCR/HOOK 只能经自动入口进入。所有最终译文仍仅由 final 产生。
- 每次绑定新的游戏窗口返回新的 game_session_id；PID/HWND 不持久化。line_id 在一个 game_session_id + epoch 中从 1 严格递增。同一 line_id 的 preview/stable 文本必须一致；变化的文本必须新 line_id。
- event_id 用 UUID；相同 ID 和相同对象幂等返回已有结果，ID 内容冲突返回 REQUEST_CONFLICT；过期游戏、场景、台词分别返回 STALE_GAME、STALE_EPOCH、STALE_SEQUENCE。重连先取状态，不盲目重发。

## 游戏会话

所有新增调用仍是 127.0.0.1 + Authorization Bearer，桌面带 X-Client-Id（进程内随机 UUID，非持久化凭据）。只允许当前宿主更改已绑定会话。

| 路径 | 输入及行为 |
| --- | --- |
| GET `/game-session` | 当前绑定、前台、手动暂停、epoch、运行能力与恢复状态 |
| PUT `/game-session` | action 为 bind/heartbeat/pause/resume/reset/unbind；bind 含 profile_id/pid/hwnd；heartbeat 含 foreground、native_subtitle、ocr_available、hook_available、可选 notice |
| POST `/text-events` | 下述台词事件；202 返回 accepted、request_id（preview/empty 为 null）、stable 的实际 sequence |
| GET `/subtitle/events` | SSE，每次变更发送 `event: subtitle`，data 为 `{subtitle,game_session}`；5 秒心跳；断线重连立即得到完整当前快照 |
| POST `/ocr-frame` | 当前宿主提交裁好的 PNG，头 X-Game-Session/X-Epoch；最大 2MiB/200万像素；返回 text、scores、ocr_ms 和归一化 text_bounds/text_regions；小字号上标假名注音从台词正文移除，raw_text 保留完整识别结果。只识别、不自动推理，稳定选择仍经 text-events |

示例事件：
```json
{"game_session_id":"game-uuid","epoch":1,"line_id":2,"event_id":"uuid","phase":"stable","source_kind":"hook","source_text":"今日は晴れです。","speaker":null,"captured_at":"2026-10-11T00:00:00Z","timings":{"capture_ms":0,"ocr_ms":0,"stable_wait_ms":300}}
```

后端终态及历史的 `timings` 保留上述采集字段，并追加 `queue_ms`、`inference_ms`。2026-10-14增加可选模型分段：`model_prepare_ms`（提示构造及模板/分词预算请求）、`model_first_token_ms`（推理请求开始至首个内容片段，包含预填充与本机传输）、`model_decode_ms`（首个内容片段至流结束）、`model_slot_release_ms`（关闭流并确认计算槽释放）、`model_generation_ms`（该次生成全程）。首字字段不是纯预填充测量；无内容片段时不提供首字/解码字段。

`generation_count`包含首次生成及修复生成；各`model_*`为同一请求内生成次数的合计，`repair_ms`是首次生成之后的全部生成耗时。`inference_ms`已包含这些耗时，不能再把各分段和修复时间加到它上面。取消或失败保留已完成测量，未开始生成的请求次数为0；仅后台测量使用分段，不能替代最终屏幕呈现时延。

质量失败证据只写入已有轮转`logs/client.log`，不新增公开诊断端点，不进入字幕/Backlog历史字段。`translation_quality` JSON记录携带四要素身份，关联首次原文/上下文/术语、原始输出/规范化输出、修复尝试及终态；文本字段最多8000字符，截断列在`truncated_fields`。原文历史仍按既有规则保存。

生成函数直接抛出`FORMAT_DAMAGE`或`GENERATION_TRUNCATED`时，`generation_error`记录原始已接收片段、意外推理片段、finish_reason和是否处于修复阶段，再关联终态；公开错误保持原有字段。独立`real_model_choice.py`入口采用相同1MiB、两份备份的轮转规则，在结果文件旁写`.quality.log`，无需先启动浏览器后台；退出还原日志级别与HTTP覆盖。

phase 为 preview/stable/empty。新 preview 或 empty 在原子锁内取消旧请求、推进 sequence、清除旧译文并使 request_id=null；preview 状态为 capturing，empty 为 idle。稳定原文才创建推理请求并先写 SQLite；未就绪时只保留一个最新 pending，新事件取代它时旧原文仍留下 cancelled 记录。等待模型不会自动重复创建请求。

手动暂停取消当前请求、清空不完整译文且禁止新采集；resume 恢复。reset 递增 epoch、清空上下文及旧台词身份，保留历史。Alt+Tab 只改变 foreground 和字幕可见性，不清空翻译上下文。稳定文字等待由桌面聚合器完成，OCR 推理由 Python 后端执行。

## 配置、运行和兼容

PUT `/profiles` 新增可选 game 对象：executable、input_mode（ocr/hook）、region（客户区归一化 x/y/width/height）、anchor（相对偏移 dx/dy）、hook（code/name/context/context2）、enabled、auto_recovery、hotkeys。省略 game 保留原值；原 prefs/glossary/history 不变。SQLite 新增 game JSON 列，显式列名写入；旧配置默认空对象。

浏览器独立模式继续可用。桌面每 15 秒续 /lease，游戏窗口每 200ms heartbeat；设置页面关闭不释放桌面租约。宿主 heartbeat 超过 8 秒未到则取消游戏并停止所属模型；通用租约仍保持 90 秒兜底。游戏退出 unbind，停止模型，桌面托盘等待；完整退出 shutdown。

capabilities.text_events 仅在游戏已绑定且至少一条取词路径实际可用时为 true。新增 capabilities.ocr/hook：OCR 要求宿主 WGC/组件校验与后端 OCR 运行时/模型校验均通过；HOOK 要求宿主已校验并运行 CLI。没有宿主、组件缺失或断开时相应能力为 false。native_subtitle 只有实际宿主报告原生字幕窗口在线时为 true；auto_recovery 仅绑定且配置启用时 true。`game_session.ocr_available` 同样结合后端校验结果，不能仅凭宿主布尔值宣称可用。

GPU 恢复仅处理 VRAM_LOW；连续 15 秒可用量≥3072MiB、保持2048MiB保留阈值后尝试降层重启。30/60/120秒退避，10分钟最多3次尝试；手动停止、监测失败、非显存错误不自动恢复。仍在等待模型的 pending 保持原 request_id；已以 error 结束、仍属于当前台词的请求以新 recover-* 身份恢复，保留原终态与历史。

2026-10-11 根据玩家“日常仍开启动态壁纸”的补充：桌面游戏会话允许 CPU 兼容模式，GPU 预算不足而可用量仍≥2048MiB时以 `--device none --no-kv-offload --gpu-layers 0` 运行 GalTransl，同样采样并保护显存余量。不自动停止壁纸或其他应用。运行中因显存不足停止后，CPU 恢复要求≥2048MiB连续15秒，使用同一失败次数和退避限制；CPU/GPU 目标切换时重新计算15秒稳定时间。`status.model.execution_mode` 和 `game_session.execution_mode/recovery_target` 明确报告实际模式。CPU 延迟单独报告，不能用GPU实测替代。浏览器独立模式保留原2560MiB启动门槛。

## OCR、依赖与验收口径

WPF 用 Windows Graphics Capture 抓帧并裁区域；Python 独立 OCR worker 使用 RapidOCR 3.10.0 + ONNX Runtime CPU，模型固定 PP-OCRv4 日文 mobile，不使用 .NET RapidOCR 绑定。所有运行依赖及模型在构建时下载、锁版本与 SHA256，运行时禁止网络下载。

桌面自动缩小过大的帧并控制PNG字节上限，区域仍按原客户区归一化坐标保存。位置依据实际文字边界，页面累积文字时只提交新增行，并避免译文覆盖已显示的原文；历史保留每次实际提交的完整新增正文。句末句号的识别闪烁不形成新台词；长度≥12字符、仅一个字形的OCR变化需要持续1500ms且至少3次相同识别，以免罕见字导致反复清屏与推理。持续的真实单字变化仍会提交，这类情况额外计入稳定等待。HOOK不使用该OCR防抖。

SeaBed 实测补充：OCR 历史保留原始多行识别文本；中文译文的视觉换行允许按长度重新排版，换行数不同记为 `ocr_line_reflow` 提示，变量/控制符损坏、空输出和生成截断仍失败。手动、剪贴板与HOOK继续严格校验换行。远离正文、字号或左边缘不相容的装饰块在存在长正文锚点时排除，纯短句不使用此筛选。累积页追加新行时，已显示前缀只容忍一个OCR字符差异；前缀≥80字符时最多容忍两个。没有新增行、差异更多或页面清空时保留整段新原文，避免误删新句。

OCR 会修正仅一侧不匹配、可明确配对的外层引号，并保留修正前 raw_text；不把所有合法引号统一替换。识别波动清除字幕后，如果同一台词再次稳定且当前没有 final/streaming 字幕，会恢复提交。2026-10-11 的真实 SeaBed 验收仍发现同一行追加、旧行多个标点变化导致整页重复，以及短句背景干扰、提示词回显和超长字幕遮挡。上述新增行行为尚未达到验收标准，详见 [SeaBed 新增行与 CPU 实机验收](SeaBed-新增行与CPU实机验收.md)，不能依据单元检查通过宣称真实游戏验收通过。

Textractor 使用官方独立 CLI 进程及匹配位数的 hook DLL，不直接链接 WPF；发布目录随附 GPL-3.0、上游版本/归属、完整对应源码归档及构建说明。OCR 包和模型、GalTransl 模型分别保留其许可证，不把它们混写成同一个许可。

## 2026-10-11 后续修复：校验与主动 Backlog

新增游戏配置 `subtitle_placement`，枚举 auto/above/below/left/right/outside，旧配置缺省为 auto；优先方向不足时仍按安全空隙回退。保存在已有 game JSON，无需重写历史或建立新 SQLite 列。PUT /profiles 省略 prefs 时在锁内保留已有显示偏好；省略 game 时保留已有游戏配置。原生单独保存位置不覆盖浏览器字号、透明度等偏好。

新增可选 `game.dialogue_box`，采用与region相同的客户区归一化x/y/width/height校验。它代表整个内置对话框，包含可摆放的空白，独立于OCR取词region；清除时在完整game对象中省略该字段。原文完整边界位于该框内且有足够安全空间时优先框内摆放；框外特殊演出使用原避让路径，outside偏好仍优先游戏外侧。不自动推断游戏对话框，也不覆盖原文。

新增 `game.hide_input`，旧配置缺省none；支持none、mouse_left、mouse_right、mouse_middle与key:A–Z / 0–9 / F1–F12 / Space / Tab / Escape（例如key:F8）。不接受组合键。此为桌面局部显示配置，不分配台词序号、不提交翻译、不暂停采集。按一次隐藏，再按一次恢复最新状态；仅绑定游戏实际前台生效，忽略按住重复、修饰键组合、设置/阅读窗和字幕操作按钮。原始输入继续交给游戏，客户端不吞键或阻止点击。取消绑定/退出释放监听；注册失败由桌面提示并保留原快捷键入口。

字幕用固定安全空间保持位置，限于所选空隙。长译文优先转能完整显示的备用区，并保持扩展位置；没有安全空间时提供主动“当前句全文”入口，不默认将截断内容交给Backlog。仍有效的方向与矩形随游戏平移，轻微OCR边界变化不切换方向；窗口大小、DPI、玩家偏好或原文侵入原位置时重新计算。旧配置缺省底衬不透明度62%，不强制覆盖已保存opacity；文字透明度保持独立。

原生字幕正文继续穿透，独立小按钮区提供Backlog、位置和当前句全文入口，不采用整窗取消穿透。位置窗口只能由玩家打开；允许按游戏保存方向、恢复自动位置或暂时隐藏。按钮窗使用NOACTIVATE/MA_NOACTIVATE；明确查看历史或编辑设置时才切换焦点，采集随前台状态暂停。普通台词优先上/下，竖排优先右/左，安全空隙不足则尝试屏幕工作区的游戏外侧，避开实际窗口边框与任务栏。所有位置都不足时收起正文，小控件也仅在能避让原文时保留；否则使用托盘或快捷键，不自动打开历史。同样原文发生位置演出时更新保护边界，不重提请求或回放译文。

已完成 OCR 文本的短暂空帧需连续约400ms确认才清空；长度≥4的单字波动（≥80字符时允许两个替换）需同一变体持续1500ms且至少3次识别才作为新台词，HOOK不使用此容错。内容相同而标点/视觉换行改变时保留 final 身份及字幕。持续8秒不能稳定的 OCR 候选发出一次 empty 清除未完成内容，随后保持安静直至新文本稳定再自动提交；不把未稳定识别结果冒充译文。

首次输出为空、变量损坏、回显提示词或明显过长时，最多进行一轮自动修复，沿用请求四要素和同一历史行；新台词/重置/取消后不得继续旧请求修复。修复不使用历史上下文。新增错误码 EMPTY_TRANSLATION、PROMPT_ECHO、OUTPUT_TOO_LONG 区分原因；format_damage 仍阻止变量/控制符损坏，包括未编号 printf 变量与引擎控制符顺序改变、转义换行丢失；命名变量及显式编号 printf 可按译文语序移动。手动与剪贴板普通多行可有界逐行重译（最多8行）；HOOK分行保持原严格拒绝语义。正常化可明确恢复的格式记 normalized_format，成功修复记 translation_repaired。meta 可带 status=retrying、replace_buffer=true，前端清除首次草稿；自动OCR/HOOK只显示校验通过的最终译文。

Backlog只经玩家按钮、托盘或可配置 backlog 快捷键（默认 Ctrl+Shift+B）打开。启动和新台词不打开历史，打开期间也不自动刷新/滚动；读取仅使用已有按游戏过滤的 GET /history。关闭/游戏变化后的迟到历史结果不显示，历史不回写实时字幕。新增行逻辑支持多行页面同一行续写、引号漂移及换行重排；明显旧正文变化仍回退完整原文，其真实去重效果须重新验收。详见 [当前优化与接续](2026-10-14-优先问题后台优化.md)。

两款老游戏以 HOOK 为主要验收，OCR 独立报告。每游戏每路径50句，按人工转录对比原始 OCR：CER=(替换+删除+插入)/参考字符数，忽略比较时的空白差异，但历史原文不改。CER≤5%、漏捕≤2%、同一台词重复提交≤1%才判 OCR 合格；不合格明确标注该游戏推荐 HOOK，不以流式翻译成功替代识别质量。

分段记录 capture_ms、ocr_ms、stable_wait_ms、queue_ms、inference_ms、display_ms；HOOK 的 OCR 段为0。分别报告两条路径中位/P95；≤1.5s/≤3s为目标，超过必须报告瓶颈，不放宽或隐去稳定等待。真实验收≥30分钟，模拟仅覆盖协议/状态和坐标，不能代替实机。

Magpie 使用 Per-Monitor V2 和未虚拟化坐标，放行注册的 MagpieScalingChanged 消息，并以事件+200ms低频核对处理层级竞争。默认不提权、不自动修改 Magpie 设置。原生宿主和已交付浏览器模式分别验收，逐阶段报告完成状态。


## completion-1增量接口

此前/bootstrap新增desktop_protocol=1和backend_build；当前已由下述协议2替代。PATCH /profiles按id局部原子更新，省略字段保留；prefs、hotkeys、anchor合并，几何对象整体校验。prefs中的null清除显式值；game.dialogue_box、special_region、hook的null移除对应可选字段。未知字段或无效合并不保存；旧PUT不变。

新增可选game.special_region，与region采用相同坐标校验，仅在常规空帧确认后回退并串行探测恢复。全文入口读取当前句快照，不读/history、不回写字幕。长译文优先完整安全备用区，仍无空间时才收起并提示当前句全文。详见2026-10-11-后台优化与接续.md。

## reliability-2增量接口与恢复

GET `/bootstrap`保持原api、token、ui_contract字段；desktop_protocol=2，backend_build=reliability-2，新增非空backend_root、database_path和instance_id。根与数据库均为已解析绝对路径；instance_id每次后端启动重新生成。桌面验证协议及预期根/数据库后才接入；路径大小写和尾部分隔符等价。其他根、数据库、旧协议或占用端口拒绝连接，不终止非所属进程。浏览器基础入口保持兼容。

每个数据库持有操作系统独占锁，第二个后台即使改用其他端口也不得打开同一数据。后台已退出时可重新启动；仍存活但连续至少三次连接失败、持续至少60秒时，仅桌面自己创建并持有Job/进程句柄的后台允许回收。10分钟内最多两次，成功探测清空连续失败计数，不清空重启预算；共享后台只重连。恢复读取状态后再恢复绑定、手动暂停及隐藏状态，不盲目重发推理。

原生字幕快照验证game_session_id和epoch：未恢复游戏身份时不接受绑定窗口快照；字幕epoch必须等于会话epoch且不早于已显示值；同epoch下旧sequence被拒绝，同sequence出现不同非空request_id也被拒绝。新的reset epoch允许sequence=0/request_id=null。后端请求四要素门禁保持原规则。

数据备份与停止后恢复由离线data_tools.py提供，不新增远程数据覆写接口。备份使用SQLite backup捕获已提交WAL；恢复先校验数据库，拒绝活动日志、当前锁或旧客户端打开的文件，再原子替换目标。玩家历史/术语/偏好不重建。实现与验证见 [当前优化与接续](2026-10-14-优先问题后台优化.md)。

## 实机修复补充（2026-10-12）

`game_session.recovery`新增`waiting_owned_stop`：游戏启动画面换成主窗口时，如先前所属模型还在停止，等它完成退出再启动；不把该暂态记为永久blocked。`recovery_error`为可选错误对象或null，保留不可恢复启动错误的code/message；心跳notice不能清除它。blocked期间接受的最新原文仍进入历史，并以对应错误结束，不能无限停在排队/翻译中。外部模型端口冲突仍不自动处理。

桌面保存HOOK线程要求模块相对code与固定上下文。当前候选拒绝保存或重新插入绝对JIT地址及动态上下文；已有此类旧配置继续保留，实际取词退回OCR并显示提示。这是当前支持边界，不表示所有引擎已支持自动HOOK恢复。

## 模型设备选择增量（2026-10-13）

GET `/settings` 返回全局 `theme`、`model_mode`（auto/cpu/gpu）与 `gpu_reserve_mib`（严格整数2048/1536/1024）。旧theme行只在读取时补默认auto/2048，无需改写历史或迁移表。PUT / PATCH接受非空局部对象，省略字段保留；拒绝未知字段、布尔/字符串预留及无效值。响应额外携带瞬时 `model_reloading`，它不属于持久化偏好。旧theme-only PUT继续兼容。

设备或预留改变先原子保存，异步取消未完成请求、停止所属模型、配置并按原运行状态重启。不同设备设置重载并行提交报409 `MODEL_RECONFIGURING`；重载中手动推理同样报409，自动事件仍只保留最新有效待处理句。完成句保留，不重新入队；同场景仍有效的未完成自动句允许使用新request_id及后端sequence恢复。暂停、手动停止、解除绑定及退出均能阻止恢复，旧身份结果不能写入当前字幕。客户端退出后start报 `CLIENT_CLOSING`。保存失败不改变运行设置；重载失败保留已保存选择并上报错误，手动start会重新应用选择。

`status.model_preferences`报告保存偏好，`status.model_reloading`报告重载；`model`新增 `requested_mode`、`gpu_reserve_mib`、`gpu_monitor_required`，实际 `execution_mode=cpu/hybrid/gpu`与 `gpu_layers`继续保留。`capabilities.model_device_choice=true`表示支持选择；字幕SSE新增相同的偏好、重载标记、model及engine_state，用于桌面设置同步。序号、来源枚举与字幕身份契约不变。

明确CPU以0层GPU启动，不依赖NVIDIA监测；CPU模型就绪后不因显存不足停止，不自动升级GPU。明确GPU要求至少一层GPU，预算不足以VRAM_LOW停止/等待，保留选择并禁止CPU兼容回退。auto沿用原策略：桌面允许CPU兼容，浏览器独立模式保留原GPU启动策略。GPU运行最低预留为所选值，启动门槛为所选值加512MiB；权重及缓冲另计。自动降层恢复稳定门槛为预留加1024MiB，明确GPU降层上限最低一层，仍保留15秒稳定期、退避及次数限制。该补充替代上文固定2048/2560/3072门槛；默认2048的GPU门槛保持原值。

`ui_contract`更新为connected-layout-2，桌面协议保持2。连接页缺少设备控件时明确拒绝不完整布局；Mock禁用真实设备保存；旧后台无model_device_choice能力时界面禁用控件并提示升级，不冒充已成功切换。

## 自动壁纸释放增量（2026-10-13）

全局`/settings`新增严格布尔`wallpaper_relief`，默认true；GET补齐旧行，PUT/PATCH局部合并。主题保存保留该值，修改策略沿用设备安全重载流程。明确CPU/GPU选择不变。GPU启动预算不足以完整加载模型，或明确CPU运行时，可检测已运行Wallpaper Engine；该应用及同目录渲染进程的专用GPU内存≥1024MiB才调用官方stop。监测/组件缺失时轻量提示并继续原预算；GPU依然不自动退CPU。释放后GPU重新采样并计算层数，最多等待5秒；取消检查避免迟到停止壁纸。

`status.wallpaper`及字幕SSE新增`available`、`enabled`、`state`、`held`、`message`、`wallpaper_gpu_mib`。state为idle、not_running、light、stopped、restored、busy、unavailable或restore_failed。`capabilities.wallpaper_control`表示该运行入口提供控制适配器；它不表示实际安装/正在运行，也不保证资源释放成功。旧后台无字段时禁用壁纸控件，保存其他设备设置不发送新增字段。Mock禁用操作。`ui_contract`升级connected-layout-3，桌面协议仍为2。

壁纸控制不写Wallpaper Engine配置，也不终止其主应用，只对本客户端拥有的stop恢复play。模型正常停止/失败、游戏退出与客户端退出恢复；设备重载期间保留租约，取消重载或退出后释放。跨便携目录共享当前用户`%LOCALAPPDATA%/GalTranslClient/wallpaper-relief.json`及操作系统文件锁，控制前原子保存恢复意图；锁跨线程可释放，进程退出自动释放锁。恢复核对原进程PID、创建时间及完整路径，已退出/重启的应用不重新启动。异常退出后下一次客户端启动补偿；恢复失败保持记录并有界定时重试，退出再做恢复尝试。关闭后的旧控制器撤销操作权，迟到回调不得操作新租约或删除新恢复记录。

按玩家最新要求，先行版GPU/混合中位目标为≤2秒，P95暂保留≤3秒；CPU目标保持既有值。真实壁纸释放、资源增益和游戏时延下一轮验证；本轮仅后台、配置及离线包检查。
