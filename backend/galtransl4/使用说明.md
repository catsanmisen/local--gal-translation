# GalTransl 4B 日常使用

当前只保留 **GalTransl-v4-4B-2601 Q6_K**。模型、运行库、本地接口及粘贴翻译窗口已实测。下载完成后的日常翻译可离线进行。

目录：`E:\GalTranslClient\backend\galtransl4`。

## 最简单：粘贴台词

1. 双击 [启动GalTransl翻译.cmd](E:/GalTranslClient/backend/galtransl4/启动GalTransl翻译.cmd)，保持窗口打开，等待 **Ready**。
2. 双击 [粘贴日文翻译.cmd](E:/GalTranslClient/backend/galtransl4/粘贴日文翻译.cmd)，粘贴一条日文，按回车即可看到中文。
3. 结束时双击 [停止GalTransl翻译.cmd](E:/GalTranslClient/backend/galtransl4/停止GalTransl翻译.cmd)，释放模型显存。

粘贴窗口保留最近最多 4 条中文译文作为前文。`/reset` 清空前文，换作品、换场景或人物关系混淆时使用；`/quit` 退出粘贴窗口，模型服务仍需单独停止。原文未明确性别但译文补出他/她的句子会提示复核，并暂不写入自动前文。

逐句或分短段翻译。粘贴多行会按行处理；要把多行短段作为整体，使用下面的 `--file` 方法。不要将整本小说或整份游戏脚本一次放入 2048-token 上下文。

## Galgame 实时显示：LunaTranslator

LunaTranslator 支持 SakuraLLM & GalTransl 专用提示格式。[官方接口说明](https://docs.lunatranslator.org/zh/guochandamoxing.html)

先启动本机服务，再在 LunaTranslator 的翻译接口中选择“特定离线翻译模型”或对应的 Sakura/GalTransl 接口：

| 项目 | 设置 |
|---|---|
| API 地址 | `http://127.0.0.1:18038/v1` |
| 模型 | `galtransl4-ja-zh`；可以刷新模型列表选择 |
| 提示格式／prompt 版本 | **GalTransl** |
| API Key | 必须填写时填 `local` |
| 源语言／目标语言 | 日语／简体中文 |
| temperature | `0.1` |
| top_p | `0.8` |
| max_tokens | `384` |
| 前文数量 | 先用 `2`，需要时增至 `4` |

游戏文本优先用 HOOK 提取，无法提取的画面文字再用 OCR。人名、称呼和专有名词在软件的专有名词翻译／术语表中固定，备注只写已确认的人物信息。换作品时清空历史。

若使用“大模型通用接口”，使用相同地址和模型名，把 `gal_translate.py` 中的 `SYSTEM` 设为系统提示，并按发布者格式组织历史译文、术语表和当前台词。不同版本的设置项名称可能有所区别。

已实测本地 API，尚未操作实际游戏或 LunaTranslator 窗口。软件设置完成后先用一条日文确认输出，再开始自动翻译。

## 广播剧

GalTransl 处理文本。先把音频识别为日文，再交给上述接口生成中文字幕；当前部署没有包含音频采集或语音识别器。

以完整短句送入翻译，保留近期前文。多人重叠、低声台词和识别错误需要另测；此前约 0.73 秒的结果仅代表文本翻译阶段。

## 命令行、词表和短段文件

翻译一句：

```powershell
python -B "E:\GalTranslClient\backend\galtransl4\gal_translate.py" "好き。……なんて、今さら言えるわけないじゃん。"
```

读取 UTF-8 短段和词表文件（把示例文件路径换成你的真实路径）：

```powershell
python -B "E:\GalTranslClient\backend\galtransl4\gal_translate.py" --file "C:\你的文本目录\日文短段.txt" --glossary-file "C:\你的文本目录\词表.txt"
```

词表每行一项：

```text
美咲->美咲 #角色名
蓮->莲 #角色名
白鳥学園->白鸟学园 #学校名
```

也支持 `--glossary "蓮->莲；美咲->美咲"`、`--context "中文前文"`、`--context-file "前文文件路径"`。日文前文含假名时会先翻译一次，增加首次请求耗时，优先复用已有中文历史。

`--json` 输出原文、译文和规则复核标记，便于保存记录。普通模式把译文写到标准输出，复核提示写到标准错误输出。客户端会检查 `{player_name}`、`%s`、`[wait]` 等变量／控制符数量和换行数量，受损时返回错误。

第三方软件直接调用原生 API 时，需要自行检查格式。规则风险标记也不能识别全部语义错误；看到“需复核”时，应对照原文、人物信息和前文。

## 状态、显存及故障检查

```powershell
python -B "E:\GalTranslClient\backend\galtransl4\gal_service.py" status
```

`ready` 表示可使用，`loading` 表示正在加载，`stopped` 表示已停止。启动后可查看 `http://127.0.0.1:18038/v1/models` 确认模型列表。

使用 2048-token 上下文、单并发、8 个 CPU 线程。GPU 层数随当前余量自动调整，目标保留至少 **2048MiB 显存**。低于目标或连续无法监控时服务会停止；启动前空闲显存少于 2560MiB 时拒绝加载。这是采样监控与停止机制，不是显存硬隔离。

每次启动覆盖服务日志和显存采样，减少旧日志积累。`runtime` 是必要运行库，应保留整个 `outputs` 目录，不要只复制模型文件。

无法连接时检查服务窗口是否显示 Ready、地址与模型名是否正确、服务是否因显存不足停止。输入过长时缩短前文或分段。关闭启动窗口会停止服务，使用时应保持窗口打开。

需要重新检查时，先停止服务，再双击 [检查GalTransl部署.cmd](E:/GalTranslClient/backend/galtransl4/检查GalTransl部署.cmd)。它会校验模型、临时启动服务、测试接口、样例、JSON 和粘贴窗口，最后停止服务并保存“部署检查结果.json”。
